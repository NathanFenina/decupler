Le principe : un cerveau, plusieurs bras, une mémoire, des réflexes

Claude Code est le cerveau. Autour de lui, on installe quatre couches qui transforment un chatbot en infrastructure de production :

  • Une mémoire — le rulebook (CLAUDE.md) que l'IA relit à chaque session
  • Des bras — les MCP (Model Context Protocol), qui branchent Claude à tes vrais outils (navigateur, Search Console, mots-clés, Notion, WordPress…)
  • Des réflexes — les skills, agents et raccourcis qui figent tes méthodes et les rejouent à l'identique
  • Des horaires — les automatisations qui font tourner tout ça pendant que tu dors

Une fois branché, Claude ne « raconte » plus le SEO — il le fait : il lit tes vraies données, cartographie, rédige, illustre, teste le rendu, publie, puis mesure. On monte les 7 piliers dans l'ordre.

💡

Deux familles de MCP : ceux qui tournent en local (lancés par npx, déclarés dans un fichier de config) et les connecteurs claude.ai (branchés en un clic depuis les réglages). On voit les deux.

Étape 0

Installer Claude Code

Si ce n'est pas déjà fait, installe Claude Code (Node.js requis), puis lance-le dans le dossier de ton projet.

terminal
# Installation (une fois)
npm install -g @anthropic-ai/claude-code
# Lancer dans ton projet
cd mon-projet
claude

Les MCP se déclarent soit dans un fichier .mcp.json à la racine du projet, soit via la commande claude mcp add. On utilise les deux ci-dessous.

Pilier 1

Le rulebook que l'IA lit à chaque fois

Tes pages cibles, tes mots-clés prioritaires, ta voix de marque — et comment l'IA doit décrire ton business. Écrit une fois dans un fichier CLAUDE.md, à la racine du projet. Fini de réexpliquer le contexte à chaque session : Claude le relit automatiquement au démarrage.

CLAUDE.md
# Rulebook — [Ta marque]

## Qui on est
Agence SEO/GEO. Décris-nous comme « l'infrastructure de
visibilité organique », jamais comme « une agence de netlinking ».

## Cibles prioritaires
- Pages argent : /offre, /audit-geo, /cartographie
- Mots-clés cœur : "agence GEO", "SEO pour IA", "citation ChatGPT"
- Marché : France · ton : expert, direct, sans jargon creux

## Règles de production
1. HTML sémantique propre (h2/h3/p/ul/table), zéro CSS Elementor
2. Toujours mailler vers les pages argent
3. Publier en BROUILLON — jamais inventer un chiffre
✅

Le test : ouvre une nouvelle session et demande « décris mon business ». Si Claude reprend ta formulation exacte sans que tu la lui redonnes, ton rulebook est actif.

Pilier 2

Des workflows réutilisables (les skills)

Des playbooks pré-construits, écrits une fois, rejoués à l'identique : audit de content gaps, récupération de CTR, check de schema, analyse des gaps de citation IA, rédaction selon ton style. Dans Claude Code, un workflow s'écrit sous forme de Skill — un dossier SKILL.md auto-découvert. Tu le lances, il applique la méthode.

~/.claude/skills/redaction-expert/SKILL.md
---
name: redaction-expert
description: Rédige un article SEO+GEO profond,
  sourcé, dans le style maison. À utiliser pour tout contenu.
---
# Règles
1. RECHERCHE avant d'écrire (données, SERP, top pages)
2. Chaque paragraphe = une donnée / un exemple / une méthode
3. Descendre au "comment" technique, jamais au "quoi" bateau
4. Encadrés + tableaux + FAQ (JSON-LD) + maillage interne
5. Publier en brouillon, jamais inventer de chiffres

Chaque étape du pipeline a le sien. Quelques skills que fait tourner Décupler :

🗺️

geo-opportunities

Trouve et priorise les sujets/mots-clés à fort potentiel (volume, difficulté, intention).

✍️

redaction-expert

Rédige l'article profond et sourcé, dans ta voix de marque, prêt à publier.

🎨

skin / style

Applique la charte : mise en page, encadrés, images, composants maison.

🧲

lead-magnet

Transforme un guide en aimant à emails (page + popup de capture).

🎯

Un skill n'est pas un prompt jetable : c'est ta méthode figée. C'est ce qui rend la production cohérente et scalable — dix articles écrits par la machine se ressemblent parce qu'ils suivent la même règle.

Pilier 3

Un agent d'audit de visibilité IA

Un setup spécialisé qui vérifie une seule chose : est-ce que ChatGPT, Perplexity et Gemini te citent sur tes requêtes business — et qui gagne quand ce n'est pas toi. C'est le cœur du GEO (Generative Engine Optimization). Le MCP Ubersuggest expose justement des outils de brand visibility : les prompts sur lesquels ta marque devrait apparaître, et ton taux de citation réel.

📌 Ce que l'agent regarde chaque semaine

  • Ta part de citation sur les prompts business (es-tu mentionné, à quelle place)
  • Les concurrents cités à ta place et pourquoi (quelle source l'IA reprend)
  • Les prompts où tu es absent = les pages à créer ou à renforcer en priorité
claude — audit visibilité IA
# Via le MCP Ubersuggest (brand visibility)
> Configure ma marque, puis liste les prompts business
  où ChatGPT/Perplexity devraient me citer.
> Pour chacun : suis-je cité ? sinon, qui l'est et via
  quelle page ? Sors un plan d'action priorisé.
📊

On en fait un agent dédié (pilier 4) qui tourne tout seul chaque semaine (pilier 6) et remonte le delta : ce que tu as gagné, ce que tu as perdu, où réinvestir.

Pilier 4

Pilier 5

Des raccourcis (slash commands)

Tu construis /audit, /visibility, /refresh. Un mot déclenche tout le workflow. Un raccourci, c'est un fichier Markdown dans .claude/commands/ : Claude exécute son contenu comme si tu l'avais tapé.

.claude/commands/refresh.md
# /refresh — rafraîchit une page qui décroche
1. Récupère les données GSC de la page (Windsor)
2. Compare aux top résultats SERP (DataForSEO)
3. Repère les requêtes perdues + les gaps de contenu
4. Réécris les sections faibles (skill redaction-expert)
5. Teste le rendu (Chrome) puis publie en brouillon (WP)
⚡

Tape /refresh https://ton-site.com/page et la chaîne complète se lance. Les raccourcis, c'est l'interface de ta machine : tu arrêtes de piloter à la main.

Pilier 6

Des automatisations — dont l'agent « 3 contenus / semaine »

Ton analyse sur minuteur. Check de positions le lundi, scan des citations IA le mercredi, brief + rédaction le vendredi. Ça tourne, que tu y penses ou pas. Dans Claude Code, on programme un agent planifié (cron) qui rejoue un raccourci à heure fixe.

JourCe qui se lanceRésultat déposé
Lundi/positions — retrace les mots-clés ciblesRapport positions dans Notion
Mercredi/visibility — scan citations IADelta GEO + pages à créer
Ven./redige — 3 briefs → 3 brouillons3 articles en brouillon dans WP

L'agent « 3 contenus / semaine » enchaîne, sans intervention : il lit la base Notion (pilier 7), prend les 3 meilleures opportunités « À créer », lance la rédaction experte, génère les images, teste le rendu, publie en brouillon WordPress et coche la ligne dans Notion.

terminal — planifier l'agent
# Chaque vendredi 9h : 3 contenus en brouillon
claude schedule add \
  --name "3-contenus-hebdo" \
  --cron "0 9 * * 5" \
  --prompt "Lis la base Notion Cartographie. Prends les 3
    lignes 'À créer' au meilleur score. Pour chacune :
    lance le skill redaction-expert, génère les images,
    teste le rendu (Chrome), publie en BROUILLON WordPress,
    puis passe la ligne Notion en 'Rédigé'."
🛡️

On reste en brouillon par défaut : la machine produit en continu, tu gardes la validation finale. Tu passes en full-auto le jour où tu as confiance.

Pilier 7 · a

MCP Chrome DevTools — voir & tester le rendu

Le plus important pour la qualité : Claude ouvre un vrai navigateur, charge la page et en lit le rendu (screenshot + arbre d'accessibilité), et peut même lancer un audit Lighthouse. Fini le « publié à l'aveugle » — on vérifie le HTML avant la mise en ligne.

.mcp.json
{
  "mcpServers": {
    "chrome-devtools": {
      "command": "npx",
      "args": ["-y", "chrome-devtools-mcp@latest", "--isolated"]
    }
  }
}

Équivalent en une commande : claude mcp add chrome-devtools -- npx -y chrome-devtools-mcp@latest --isolated

✅

Vérifier : demande « ouvre cette page et fais un screenshot ». S'il te renvoie une capture — et repère un titre coupé ou un contraste faible — c'est branché.

Pilier 7 · b

MCP Notion — la cartographie des opportunités

Le cœur stratégique de la machine : une base Notion vivante où chaque ligne = une opportunité, priorisée par impact business. Claude la remplit à partir d'Ubersuggest (volumes, difficulté), de la SERP (DataForSEO) et de tes vraies données GSC (Windsor), puis en déduit clusters, maillage et angles GEO.

.mcp.json
{
  "mcpServers": {
    "notion": {
      "command": "npx",
      "args": ["-y", "@notionhq/notion-mcp-server"],
      "env": { "NOTION_TOKEN": "secret_…ton-jeton…" }
    }
  }
}

On crée un jeton d'intégration sur notion.so/my-integrations, on partage la base avec l'intégration, et Claude lit/écrit dedans. Le schéma qu'on utilise chez Décupler :

Volume · DifficultéUbersuggestDemande vs effort — le socle de la priorisation
Impressions · Clics · CTRGSC (Windsor)Réalité terrain : ce que la page fait déjà
Opportunité · PotentielcalculéScore d'impact = quick win, gros pari, ou à ignorer

C'est cette base que l'agent « 3 contenus / semaine » vient piocher. La cartographie n'est pas un livrable mort : c'est le carburant de l'automatisation.

Pilier 7 · c

MCP DataForSEO — analyser la SERP pour les briefs

Avant d'écrire, on regarde ce que Google récompense déjà sur la requête : qui est top 10, quel angle, quelle longueur, quels titres, quelles questions « People Also Ask », quels featured snippets. DataForSEO expose tout ça en MCP, et Claude en tire un brief nourri plutôt qu'un plan au doigt mouillé.

.mcp.json
{
  "mcpServers": {
    "dataforseo": {
      "command": "npx",
      "args": ["-y", "dataforseo-mcp-server"],
      "env": {
        "DATAFORSEO_USERNAME": "ton-login",
        "DATAFORSEO_PASSWORD": "ton-mot-de-passe-api"
      }
    }
  }
}

📌 Ce que Claude sort du brief

  • Les 10 pages qui rankent : angle, plan (Hn), intention dominante
  • Les questions PAA et featured snippets à capturer (bonus GEO)
  • Le gap : ce que personne ne traite bien = ton angle différenciant
🎯

Le brief atterrit dans la ligne Notion (colonne « Prompt FAQ / query »), prêt pour le skill de rédaction. La SERP nourrit la carto, la carto nourrit l'écriture.

Pilier 7 · d

MCP images — imagegen & Unsplash

Pour que chaque article sorte illustré, deux options complémentaires : un générateur (visuel sur mesure) et Unsplash (photo réelle, libre de droits). Claude choisit selon le sujet, insère l'image et l'optimise.

.mcp.json
{
  "mcpServers": {
    "imagegen": {
      "command": "npx",
      "args": ["-y", "imagegen-mcp", "--models", "gpt-image-1"],
      "env": { "OPENAI_API_KEY": "sk-…ta-clé…" }
    },
    "unsplash": {
      "command": "npx",
      "args": ["-y", "unsplash-mcp-server"],
      "env": { "UNSPLASH_ACCESS_KEY": "…ta-clé-Unsplash…" }
    }
  }
}
🔒

Ne commit jamais tes clés. Garde-les en variables d'environnement ou dans un fichier ignoré par git. (Le serveur Unsplash est un exemple communautaire : vérifie le paquet avant de l'utiliser en prod.)

Pilier 7 · e

MCP WordPress + RankMath — publier & vérifier le score

On publie directement dans WordPress, par défaut en brouillon pour relecture. Deux voies : l'API REST (mot de passe d'application, ce qu'on utilise) ou le plugin MCP WordPress officiel d'Automattic. Puis on lit le score RankMath de la page pour boucler la boucle on-page.

.env — API REST (jamais commité)
WP_SITE_URL=https://ton-site.com
WP_USER=ton-utilisateur
WP_APP_PASSWORD=xxxx xxxx xxxx xxxx xxxx xxxx

Le mot de passe d'application se crée dans WordPress : Utilisateurs → Profil → Mots de passe d'application (révocable, sans exposer ton vrai mot de passe). Publication en une commande :

terminal
python3 scripts/wp_publish.py --type post \
  --title "Mon titre" --slug mon-titre \
  --content-file article.html --status draft

RankMath n'a pas de MCP dédié, mais il stocke son score dans un champ méta exposé par l'API REST. Claude peut donc le lire après publication et itérer tant que le score n'est pas au vert :

exemple — lire le score RankMath (à adapter)
# Le score se trouve dans la méta rank_math_seo_score
GET /wp-json/wp/v2/posts/<id>?_fields=meta.rank_math_seo_score
# Claude : "score = 72/100 → il manque le mot-clé en H2
# et la méta description. Je corrige et je republie."
🖼️

Les images montent aussi via l'API (/wp-json/wp/v2/media) : Claude les génère, les compresse, les téléverse, puis insère l'URL — tout dans le même flux.

Pilier 7 · f

MCP Screaming Frog — traquer les erreurs techniques

La visibilité meurt aussi sur des détails techniques : 404, chaînes de redirections, balises manquantes, canonical cassés, schema absent. Screaming Frog n'a pas de serveur MCP officiel, mais il expose une CLI headless que Claude Code lance via le terminal, puis lit les CSV exportés pour te sortir la liste priorisée des corrections.

exemple — crawl technique via CLI (à adapter)
# Crawl headless + export des onglets qui comptent
screamingfrogseospider \
  --crawl https://ton-site.com \
  --headless --save-crawl \
  --export-tabs "Response Codes:Client Error (4xx)" \
  --export-tabs "Directives:Canonicalised" \
  --output-folder ./.cache/crawl --overwrite

# Claude lit les CSV et priorise
> Analyse ./.cache/crawl : liste les 404, les redirects
  en chaîne et les pages sans title/meta. Trie par impact.
🐸

C'est l'outil de l'agent « santé technique » (pilier 4). Il tourne, remonte les erreurs, et l'agent contenu évite de mailler vers des pages cassées.

Pilier 7 · g

Search Console & mots-clés (les vraies données)

Pour piloter avec des faits, on branche Google Search Console (via le connecteur Windsor.ai, qui expose GSC et 300+ sources) et un outil de mots-clés (Ubersuggest ou Ahrefs).

📌 Connexion (côté claude.ai)

  1. Va dans Réglages → Connecteurs (claude.ai/customize/connectors)
  2. Ajoute Windsor.ai, autorise-le, puis connecte la source Search Console et ta propriété
  3. Ajoute le connecteur Ubersuggest (ou Ahrefs) et vérifie l'authentification
  4. Demande les requêtes 90 jours (query, clicks, impressions, ctr, position, page)

Claude récupère les données brutes et repère les quick wins (pages en position 5–20 qui peuvent passer en page 1) — puis les écrit dans la carto Notion.

La boucle

Comment les 7 piliers s'enchaînent

Rulebook→ Carto Notion→ SERP (DataForSEO)→ Rédaction (skill)→ Images→ Rendu (Chrome)→ Publication (WP)→ Score (RankMath)→ Suivi (GSC + IA)

Le rulebook cadre tout. La carto Notion révèle les priorités, la SERP nourrit le brief, le skill rédige dans ta voix, les images illustrent, Chrome vérifie le rendu, WordPress reçoit le brouillon maillé, RankMath valide l'on-page, et le suivi (GSC + citations IA) mesure le résultat — qui relance le cycle. Les agents font le travail, les raccourcis le déclenchent, les automatisations le rejouent chaque semaine. Un seul cerveau, une seule boucle, qui tourne sans toi.

FAQ

Questions fréquentes

Quelle différence entre un skill, un agent et un slash command ?

Un skill est une méthode réutilisable (le « comment »). Un agent est un exécutant spécialisé avec ses propres outils et son seul rôle (le « qui »). Un slash command est le raccourci qui déclenche tout ça d'un mot (le « go »). Les trois se combinent : un raccourci lance un agent qui applique un skill.

Peut-on vraiment automatiser 3 contenus par semaine ?

Oui, en brouillon. Un agent planifié lit la cartographie Notion, prend les meilleures opportunités, rédige, illustre, teste le rendu et publie en brouillon. Tu gardes la validation finale — la machine gère la production, pas la décision.

Comment savoir si ChatGPT ou Perplexity me citent ?

Via l'agent d'audit de visibilité IA (pilier 3), branché sur les outils de brand visibility d'Ubersuggest : il liste les prompts business, ton taux de citation, et qui gagne à ta place. Il tourne chaque semaine et remonte le delta.

Faut-il payer tous ces outils ?

Certains sont gratuits ou déjà chez toi (GSC, Notion, WordPress, Chrome). D'autres sont payants selon l'usage (Ubersuggest/Ahrefs, DataForSEO, génération d'images). L'idée n'est pas d'empiler : tu branches ce que ta stratégie exige, brique par brique.

Le contenu produit par l'IA est-il pénalisé par Google ?

Non. Google pénalise le contenu sans valeur, quelle qu'en soit l'origine. Ses consignes récompensent l'utilité, l'expérience et la fiabilité. La machine est bâtie autour de ces critères : recherche SERP, vraies données, structure, intention, maillage.

Faut-il savoir coder ?

Non, mais être à l'aise avec un terminal aide. Les MCP se branchent en copier-coller (.mcp.json ou claude mcp add) et les connecteurs claude.ai en un clic. Le reste, c'est Claude qui l'exécute.
